# Automatic layouts: `outlay watch` (plan)

> This file briefs the two sessions that build `outlay watch` (ROADMAP.md, issue #23). Where it
> differs from `docs/PLAN.md`, this file wins for the service and the identity lines.

## Context

ROADMAP.md "Automatic layouts" ([issue #23](https://github.com/Papayah/outlay/issues/23)): outlay
should apply saved layouts on its own when displays connect or disconnect, as autorandr does, and
never leave the laptop panel dark after the last external display goes.

Today outlay has no such service. The editor polls every 2 s only to refresh its own view, profiles
are applied by name only, and X11 scripts hold connector names with no monitor identity.

The work runs in two phases, one fresh session each, on one branch (`feat/auto-layouts`) with one
PR at the end.

## Decisions (answered by the maintainer)

| Topic | Decision |
|---|---|
| Wayland | Fail-safe only. kanshi stays the profile switcher. |
| Monitor identity on X11 | Comment lines in the script: `# outlay: DP-1-3 = Dell U2720Q 7JNY5S2`. Scripts without them match by connector names. |
| Hand-made layout | Wins until the displays change. The service reacts to plug events only. |
| No profile fits | Turn off unplugged outputs that are still on; change nothing else. |
| Two profiles fit | First by name. The log names the others. |
| Editor open | No coordination. The service applies anyway, with its own revert file. |
| Plug detection on X11 | Poll every 2 s. RandR events through `x11rb` go to ROADMAP.md as the next step. |
| systemd unit | `outlay watch --print-unit` prints it. README gives the two install lines. |

## Decisions taken in planning

1. **The service decides once at start**, as if the displays had just changed. Login is when the
   set really changes. Cost: a service restart replaces a hand-made layout.
2. **`outlay watch --once`**: decide for the current displays, apply, exit. With `-n` it only
   prints the decision and the command. It is the test seam and the "what would it do?" tool.
3. **A fresh backend per reading** (`cli.backend()` each round, dropped after). Free on X11. On
   Wayland it avoids the wlroots abort that a long-lived second client can trigger
   (`MISTAKES.md`, "`outlay restore` loses the connection"), and it survives a compositor restart.
4. **Debounce:** the service acts when two readings 2 s apart show the same connected set. A dock
   brings monitors one by one, and on Wayland kanshi gets to act first.
5. **`post_apply` hooks run** after the service's applies (the `Session` does it already).
6. **The editor's `e` and `outlay apply NAME` keep their remap as it is.** Identity matching is for
   the service only.

## Phase 1: Monitor identity in scripts and the fit check

done when: `cargo fmt --all -- --check && cargo clippy --all-targets -- -D warnings && cargo test` pass, and `cargo test fit` runs the new fit tests.

Branch `feat/auto-layouts` from `main`. Do not run anything that changes the live displays.

1. Write `docs/PLAN-auto.md` from this plan's Context, both Decisions sections and the design
   text of both phases. Commit `docs: plan automatic layouts`.
2. **Identity lines.** Commit `feat: record monitor identities in saved scripts`.
   - `src/model/profile.rs`: `Profile` gets `identities: Vec<(String, String)>`, connector name →
     `description()` text (`profile.rs:129`).
   - `src/xrandr/script.rs`: `Profile::parse` (`:189`) reads `# outlay: NAME = TEXT` lines (split
     at the first ` = `). `save_text(old, command)` (`:397`, one caller: `src/profiles.rs:239`)
     takes the identity lines too: it writes them after the `# generated by outlay` line and
     replaces old ones, as it does for that header. Every other line stays byte for byte.
   - `src/profiles.rs` `ProfileStore::save` (`:223`), Screenlayout branch: one line per connected
     output of `snap`.
3. **Fit.** Commit `feat: match a profile to the connected monitors`.
   - `src/model/profile.rs`: `pub fn fit(&self, snap: &Snapshot) -> Option<Remap>`.
   - **With identity lines:** the connected monitors must be exactly the monitors of the lines
     (compare `description(out)`). Each line's entry goes to the connected output with that
     description, the same connector first. The result is the `Remap` for entries whose monitor
     sits on another port. An on-entry without a line: no fit.
   - **Without identity lines:** every on-entry is matched by `matches()` (`:240`) and the
     connected outputs are exactly the outputs the on-entries match. Strict on purpose: a legacy
     `laptop.sh` must not turn off a newly plugged monitor.
   - Reuse `Remap`, `matches` and `layout(snap, remap)` (`:340`). A remap row may also name an
     entry that is connected (two monitors that swapped ports).

Tests (builders in `tests/common/mod.rs`, captures in `tests/fixtures/xrandr/`):
- a save writes the lines; a second save replaces them and keeps other lines byte for byte;
- a script without lines parses as before;
- `fit`: same monitors on the same ports; the monitor on another port (remap); two monitors that
  swapped ports; another monitor on the same port (no fit); one monitor more or one less (no
  fit); a legacy script with the panel off (no fit); a legacy script whose on-outputs equal the
  connected set (fit).
- Saved-script goldens change: `tests/profiles.rs`, `tests/commands.rs`, `tests/cli.rs`,
  `tests/tui.rs` and the insta snapshots (review `.snap.new` before renaming).

Do not touch `default_remap` or kanshi saving. Check the git identity after each commit
(CLAUDE.md). List any trap that cost real time in the body of the last commit message; phase 2
moves it to `MISTAKES.md`.

## Phase 2: The `outlay watch` service, docs and the PR

done when: `cargo fmt --all -- --check && cargo clippy --all-targets -- -D warnings && cargo test` pass, `cargo run -- --from-file tests/fixtures/xrandr/active-disconnected.txt --layouts-dir "$(mktemp -d)" -n watch --once` prints a decision and an xrandr command, and the PR is open.

Continue on `feat/auto-layouts`. Read `docs/PLAN-auto.md` first. The developer's screens are
live: never run `outlay watch` without `-n` or a fixture.

1. **`src/watch.rs`**, `Command::Watch { once, print_unit }` in `src/cli.rs`, dispatch in
   `src/main.rs`. Commit `feat: outlay watch applies saved layouts on hotplug`.
   - **Decide** (pure, no display):
     1. X11 only: the first profile in `ProfileStore::list()` order (`src/profiles.rs:162`,
        sorted by name) whose `fit` is `Some`. Log the other fitting names.
     2. Else the fallback layout: `Layout::from_snapshot(snap)` (`src/model/layout.rs:148`; it
        already turns stale outputs off).
     3. Fail-safe, on both kinds: when no external output is connected and a built-in panel is
        (`wayland::built_in`, `src/wayland/mod.rs:35`), the result must have the panel on. If it
        does not, take the fallback layout and `Layout::turn_on` (`src/model/links.rs:760`,
        preferred mode).
     4. An empty `layout.diff(&snap)`: nothing to do.
   - **Apply:** through `Session`, as `profile::apply` does (`src/profile.rs:89-118`); extract
     the shared part instead of copying it. Differences: `revert_seconds = 0` (kept at once; a
     failed apply still reverts, `src/tui/session.rs:482`), `revert_file` = `watch-revert.sh`
     beside `revert.sh` (`default_revert_file`, `session.rs:85`), `options.watch = None`, the
     remap comes from `fit`, never from `default_remap`. `tui::confine` (`src/tui/mod.rs:192`)
     keeps fixtures harmless.
   - **Loop:** one `step()` per round, so tests drive it without a clock: read (`requery`),
     compare the connected set (name + description) with the last set acted on, wait for two
     equal readings, then a full `query()`, decide, apply, log one line. Sleep 2 s between
     rounds, a fresh `cli.backend()` each round. Mark the poll with
     `// shortcut: polls every 2 s, replace with RandR events (x11rb) per ROADMAP`.
   - **Hand wins** needs no code: the compared set holds connections only, never positions.
   - **Log:** plain lines on stderr; never `eprintln!` (the `say` pattern, `src/profile.rs:26`).
   - **`--print-unit`:** the unit with `std::env::current_exe()` in `ExecStart`,
     `Restart=on-failure`, `PartOf=` and `WantedBy=graphical-session.target`.
2. **Docs.** Commit `docs: describe outlay watch`.
   - README "Automatic layouts": the two install lines
     (`outlay watch --print-unit > ~/.config/systemd/user/outlay.service`,
     `systemctl --user enable --now outlay`), the i3 alternative
     `exec --no-startup-id outlay watch`, how a profile fits, the identity lines, the fail-safe,
     and that kanshi does the switching on Wayland.
   - ROADMAP.md: drop "Automatic layouts"; add "RandR events through `x11rb` for `outlay watch`"
     as the next step. CLAUDE.md "Layout": add `src/watch.rs`.
3. **Finish.** Traps from both phases into `MISTAKES.md` (phase 1's are in its last commit
   body); commit. Push the branch and open the PR with the description in
   `~/workspace/claude-cage/pr-descriptions/pr-description-auto-layouts.md` (English headings, no
   attribution). End the description with a manual checklist for the user: start `outlay watch`
   in a terminal, unplug the dock, plug it back, change a layout by hand and see it stay. Do not
   merge, do not release.

Tests:
- `decide` as a table: a profile fits; two fit and the first by name wins; none fits and a stale
  output goes off (`tests/fixtures/xrandr/active-disconnected.txt`); the last external goes and
  the panel comes on, with and without a fitting profile; Wayland never switches profiles
  (`tests/fixtures/wayland/`).
- The loop with `FixtureBackend::set_state` (`src/backend/fixture.rs:70`, used the same way in
  `tests/apply.rs:921`): no action on one changed reading, action on the second, no action when
  only positions change, a failed apply reverts and the loop goes on.
- `tests/cli.rs`: `--from-file … -n watch --once` and `watch --print-unit`.
- `OUTLAY_TEST_SWAY=$(command -v sway) cargo test --test wayland_live` still passes.

## Verification

- Every commit: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test`.
- Without a display: the `watch --once` command from phase 2's "done when", and
  `cargo run -- watch --print-unit`.
- On the real dock, by the user only: the checklist in the PR.

## Not in this plan

- RandR events (`x11rb`): ROADMAP, next step.
- Profile switching on Wayland, a lock between the editor and the service, a remembered layout
  per monitor set, config keys for the interval, a unit written by `install.sh`.
- A release: only on the user's go-ahead.
